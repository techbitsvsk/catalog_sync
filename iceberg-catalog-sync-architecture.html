9. Source → Sync Engine → Target — Any cloud platform, any direction, any reason

The sync engine sits between any Iceberg source and any Iceberg target. The source and target can be cloud platforms, on-premises storage, or both — in either direction. The reason to sync — disaster recovery, data gravity, regulatory residency, cost optimisation — is a business decision. The engine does not care.

Why you might run a sync — same engine for all of these

DATA GRAVITY

Compute lives on-prem or in a different cloud. Move the data closer to eliminate egress latency and cross-cloud query costs. The table is queryable locally with any engine — Spark, Trino, DuckDB, PyIceberg — without touching the source.

Azure Fabric → on-prem MinIO + Nessie
AWS S3 → Azure ADLS (Fabric compute)
GCS → on-prem MinIO + Nessie
DISASTER RECOVERY

Keep a warm copy of critical tables on a second platform. If the primary becomes unavailable, the standby catalog is already populated and queryable. PathTranslator.reverse() syncs new data back after recovery — no code change required.

Primary Azure ADLS → Standby AWS S3
Primary AWS S3 → Standby on-prem
Primary Azure → Standby on-prem Nessie
REGULATORY RESIDENCY

Data must reside in a specific geography or jurisdiction. Sync a compliant copy into a region-locked storage account — source is never modified, target holds a fully self-consistent Iceberg table with translated URIs.

Global S3 → EU-only ADLS (GDPR)
Azure global → sovereign cloud region
Any cloud → air-gapped on-prem

Placement Best for Notes
On-prem Airflow Cloud → on-prem (Example 1) Engine runs on-prem, reads from cloud, writes to local MinIO. No cloud compute cost for the sync.
AWS — Glue Job / ECS AWS S3 → Azure ADLS (Example 2) S3 reads are free within the same AWS region. Orchestrated by MWAA or Step Functions.
Azure ADF / AKS Pod Azure ADLS → AWS S3 or on-prem ADLS reads are free within Azure. ADF wraps the CLI as a custom activity or calls the Python API.
Neutral host / VM Any cross-cloud pair Place in the region closest to both storage endpoints to minimise round-trip latency.
